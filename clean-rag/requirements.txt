# The embedding stack, pinned exactly rather than ranged.
#
# These three have to agree with each other, and a range gave them room not to.
# What actually happened: an interrupted pip run left huggingface_hub with no
# __init__.py, and transformers holding 1773 files belonging to a version its
# own dist-info disagreed with. Every embedding load failed for days. Nothing in
# a range like ">=3.0.0,<4.0" could have caught that, because every version
# involved satisfied it.
#
# The set below is checked against the packages' own metadata, not guessed:
# sentence-transformers 3.4.1 requires transformers>=4.41.0,<5.0.0 and
# huggingface-hub>=0.20.0; transformers 4.57.6 requires
# huggingface-hub>=0.34.0,<1.0. All three hold at once here.
#
# Bump these together, never one alone, and read both projects' requirements
# before you do.
sentence-transformers==3.4.1
transformers==4.57.6
huggingface-hub==0.36.2

# Required by the default code embedding model, not by us directly, which is
# why it was missed. nomic-ai/CodeRankEmbed (config.py CODE_EMBEDDING_MODEL,
# and lang_router's MODEL_FALLBACK) ships its own modeling code, and
# transformers runs check_imports on that file before downloading any weights.
# Without einops it raises ImportError there, so the model never loads, the
# server reports status "failed" with code_embedding_loaded false, and every
# /index-project answers 500. Nothing in the log points at requirements.txt.

# with a stable API, not part of the transformers/sentence-transformers version
# knot above that has to agree with itself.
