#  rerankers: A Lightweight Python Library to Unify Ranking Methods

Benjamin Clavié 

###### Abstract

This paper presents rerankers, a Python library which provides an easy-to-use interface to the most commonly used re-ranking approaches. Re-ranking is an integral component of many retrieval pipelines; however, there exist numerous approaches to it, relying on different implementation methods. rerankers unifies these methods into a single user-friendly interface, allowing practitioners and researchers alike to explore different methods while only changing a single line of Python code. Moreover, rerankers ensures that its implementations are done with the fewest dependencies possible, and re-uses the original implementation whenever possible, guaranteeing that our simplified interface results in no performance degradation compared to more complex ones. The full source code and list of supported models are updated regularly and available at <https://github.com/answerdotai/rerankers>.

##  1 Introduction

A common approach to information retrieval is the use of a two-stage retrieval pipelines: a small set of candidate documents is first retrieved by a computationally efficient retrieval method, to then be re-ranked by a stronger, generally neural network-based, model [[10](https://arxiv.org/html/2408.17344v1#bib.bib10)]. This method is used in order to mitigate latency constraints: while models frequently used for re-ranking are particularly powerful, as they’re aware of both documents and queries at encoding time [[12](https://arxiv.org/html/2408.17344v1#bib.bib12)], this efficiency comes at a prohibitive computational cost [[11](https://arxiv.org/html/2408.17344v1#bib.bib11)]. As a result, in order to use them on any larger scale document sets, it is necessary to use more lightweight method, such as BM25 [[17](https://arxiv.org/html/2408.17344v1#bib.bib17)] or DPR [[25](https://arxiv.org/html/2408.17344v1#bib.bib25)], which do not require such expensive calculation, to create a smaller set of document. This smaller set can then be processed in a short amount of time by the re-ranking model.

This approach has been widely adopted in Information Retrieval systems, consistently yielding stronger results than relying on a single retriever without re-ranking [[16](https://arxiv.org/html/2408.17344v1#bib.bib16), [9](https://arxiv.org/html/2408.17344v1#bib.bib9)]. Moreover, such models are very powerful, as their output scores can be used for knowledge distillation [[5](https://arxiv.org/html/2408.17344v1#bib.bib5)], where first-stage retrieval models are trained to emulate the scores generated by re-ranking models. Knowledge Distillation from re-ranking model scores has been consistently shown to allow the training of stronger first-stage retrievers [[2](https://arxiv.org/html/2408.17344v1#bib.bib2), [7](https://arxiv.org/html/2408.17344v1#bib.bib7), [16](https://arxiv.org/html/2408.17344v1#bib.bib16), [18](https://arxiv.org/html/2408.17344v1#bib.bib18)].

Over time, there has been an increasing number of neural re-ranking methods. Most early neural re-ranking models were cross-encoders, [[12](https://arxiv.org/html/2408.17344v1#bib.bib12)], framing the task as a binary sentence classification task and using a pre-trained encoder model such as BERT [[4](https://arxiv.org/html/2408.17344v1#bib.bib4)]. However, many new methods have appeared, such as MonoT5 [[11](https://arxiv.org/html/2408.17344v1#bib.bib11)], leveraging sequence-to-sequence models such as T5c̃itet5 rather than BERT-like models, or ColBERT-based methods, which repurpose late-interaction retrieval mdoels such as ColBERTv2 [[18](https://arxiv.org/html/2408.17344v1#bib.bib18)] as re-ranking models. Other work also explores different paradigms, such as listwise re-ranking using sequence-to-sequence models, where the model is not tasked with outputting a score for a [query, document] pairs, but rather, to directly output a list of documents ordered by their relevance to the given query [[21](https://arxiv.org/html/2408.17344v1#bib.bib21)]. Work such as FlashRank [[3](https://arxiv.org/html/2408.17344v1#bib.bib3)], has focused on optimised methods to speed up re-ranking when performed on weaker inference hardware, such as CPUs. Finally, some of the best-performing re-ranking methods, such as Cohere-Rerank [[19](https://arxiv.org/html/2408.17344v1#bib.bib19)], while observed in literature to be competitive with some of the best models [[20](https://arxiv.org/html/2408.17344v1#bib.bib20)], are currently only accessible via an online API.

Some recent approaches have also explored the use of Large Language Models (LLMs) as re-rankers. This has been the topic of a lot of attention, with some methods using very powerful LLMs, such as GPT-4 [[1](https://arxiv.org/html/2408.17344v1#bib.bib1)], to perform zero-shot listwise re-ranking [[20](https://arxiv.org/html/2408.17344v1#bib.bib20)], while others purposefully fine-tuning smaller models on the output of larger models, another form of knowledge distillation, to create powerful list-wise re-rankers such as RankZephyr [[15](https://arxiv.org/html/2408.17344v1#bib.bib15)]. Very recent work in this space has also explored the use of inference-time model compression techniques, in order to use LLM models such as Gemma2 [[22](https://arxiv.org/html/2408.17344v1#bib.bib22)] as re-rankers at a fraction of the computational cost [[8](https://arxiv.org/html/2408.17344v1#bib.bib8)].

###  1.1 Contribution

These methods all come with different trade-offs, and may be more or less well-suited to different usecases. However, the multiplication of approach makes keeping up with existing research and evaluating new methods is often needlessly difficult. In some cases, adopting a different method might require substantial code changes, due to the wide variety of dependencies and input/output formats across methods. This issue also makes it more difficult for newer approaches to reach large adoption, as their exploration represents a cost which can be prohibitive.

To alleviate these issues, we introduce rerankers, a simple, light-weight Python library which seeks to unify re-ranking methods. rerankers relies on three core principles: 1 It must provide an easy way to load, use, and swap inout various re-ranking methods, 2 It should be as non-intrusive as possible, without requiring the user to greatly modify their environment or codebase to adopt and 3 It must not result in a ranking performance degradation when compared to existing implementations. The library is compatible with all modern Python versions and provides a simple, user-friendly interface to most common re-ranking approaches. In doing so, it also comes with utility to accommodate various use-cases, such as retrieving only the top-k candidates for a given query, or only outputting scores to use for knowledge distillation.

##  2 System Overview

###  2.1 The Reranker class

Everything within the library is organised around a central class named Reranker. It is used as the main interface to load models, no matter the underlying implementation or requirements. Its interface is demonstrated in Listing [1](https://arxiv.org/html/2408.17344v1#LST1 "Listing 1 ‣ 2.1 The Reranker class ‣ 2 System Overview ‣ rerankers: A Lightweight Python Library to Unify Ranking Methods").

rerankers allows users to specify document ids and document meta-data, which are preserved post-scoring in the RankedResults object. This object also contains the original text of each document, as well as global attribute, has_scores, indicating whether or not the Results are simply ordered (by a list-wise re-ranker such as RankGPT [[20](https://arxiv.org/html/2408.17344v1#bib.bib20)]), or if each document has an individual relevance score.

###  2.3 Extensibility and Modularity

Modularity rerankers is designed specifically with ease of extensibility in mind. All approaches are independently-implemented and have individually-defined sets of dependencies, which users are free to install or not based on their needs. Informative error messages are shown when a user attempts to load a model type that is not supported by their currently installed dependencies.

Extensibility As a result, adding a new method simply requires making its inputs and outputs compatible with the rerankers-defined format, as well as a simple modification of the main Reranker class to specify a default model. This approach to modularity has allowed us to support all the approaches with minimal engineering efforts. We fully encourage researchers to integrate their novel methods into the library and will provide support for those seeking to do so.

##  3 Comparison with Existing Tools

###  3.1 Existing Libraries

As of the making of this work, no library providing a consistent API to access common reranking methods existed, as such, rerankers has no direct equivalent.

For most individual methods integrated within rerankers111With the exception of ColBERT, as all previous reranking-only public implementations suffered from issues impacting performance, an existing implementation or way to access the online API already existed. rerankers is not a direct competitor to any of these implementations. In fact, our library often re-uses parts of the original authors’ code or acts as a wrapper around their library, if a mature one with moderate dependencies exists [[15](https://arxiv.org/html/2408.17344v1#bib.bib15), [14](https://arxiv.org/html/2408.17344v1#bib.bib14), [21](https://arxiv.org/html/2408.17344v1#bib.bib21)].

###  3.2 Performance

In order to ensure performance parity with existing implementations, we conduct top-1000 reranking evaluations on three commonly used datasets222a subset of the MS Marco passage retrieval dataset, as well as Scifact and TREC-Covid, all three being subsets of the BEIR benchmark [[23](https://arxiv.org/html/2408.17344v1#bib.bib23)]..

For most models implemented in the library, over 5 runs, we achieve parity with either the existing implementation code and reported results from the litterature. A notable exception is RankGPT [[20](https://arxiv.org/html/2408.17344v1#bib.bib20)], where our results over all runs were noticeably different from the paper’s reported results 333The results we obtained were worse than the official ones in 4 runs, and better in 1.. We observed similar behaviour when using the author’s own code, and believe that this is likely due to the difficulty of reproducing experiments with unreleased, API-only models such as the GPT family [[6](https://arxiv.org/html/2408.17344v1#bib.bib6)].

##  4 Conclusion

In this work, we introduced rerankers, a lightweight python library to support the use of various re-ranking methods in various retrieval usecases. rerankers provides a simple, unified interface to using nearly all commonly encountered approaches to re-ranking in a single, lightweight package, without any detriment to performance. We hope that re-rankers will support both practitioners and researchers in the future, by considerably lowering the barrier to entry formerly present for less well-known approaches and providing easy extensibility to implement upcoming re-ranking methods within a familiar interface.

In the future, we are hoping for the rerankers library to also support fine-tuning, to simplify training and comparing in-domain models within a familiar interface.

Finally, it is worth noting that rerankers has already contributed to scholarly work, by producing the model scores used in distillation [[2](https://arxiv.org/html/2408.17344v1#bib.bib2)], or becoming the authors’ way of releasing their new Portuguese re-ranking models [[13](https://arxiv.org/html/2408.17344v1#bib.bib13)].
